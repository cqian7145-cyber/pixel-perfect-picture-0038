## 分批实施与验收

1. **工程基线核验**：PR #1 合并并同步后重查差异，运行既有相关测试；不覆盖审计方未合并工作。
2. **Style C 核心页面**：先统一颜色、字体、纸张与动效，再精修门店首页、投稿、故事阅读及抽信；对 360/390/430/768/1440px 检查可读性、导航与溢出。参考图仅作为参考，不当作真实门店照片。
3. **独立数据与身份基础**：方案批准后建立门店隔离、商家成员、匿名会话、故事、投稿、回应、审核记录、授权记录和门店设置；所有规则在服务端执行。确认用户资料需求后才写认证代码。
4. **今夜留一句真实闭环**：140 字校验、预览、明确授权、默认待审核、防重复及限流、审核公开、分页和作者撤回；错误、重试、加载均可验证。
5. **记忆馆与回忆接力**：真实精选/普通故事、标签与日期；抽取已审核信件，避免连续重复；一层回应关联原信，预览授权、审核后展示，撤回停止公开。
6. **商家与其余视觉统一**：安全登录及门店权限验证、审核原因与留痕、隐藏违规内容、精选和配置；分开验收其他七项原型与 Studio 四页的视觉，不声称原型已经上线。
7. **真实验收与交付**：顾客 A 投稿→商家审核→另一设备顾客 B 阅读并回应→商家审核→原信显示回应→作者撤回。测试未登录访问、跨门店越权、未审核泄漏、重复请求及异常反馈；未运行项明确写 NOT VERIFIED。

## Moonlight 3.0 后续方向（不在本轮自动实施）

当前三项真实闭环验收后，优先评估：**门店当前体验模式 → 驻唱活动信息 → 默认私人的数字票根 → 获授权的演出记忆档案 → 下一场活动预约**。

轻投票仅使用演出者同意的选项，最多一两个参与节点，最终由演出者决定。演出中不弹窗、不强制倒计时。音乐双人挑战需要本项目已有对应能力或单独批准开发，不能借“复用”访问其他项目。预约小组先人工试点，自动陌生人匹配和支付票务不纳入当前范围。

## 技术实施边界

- UI 仍只通过 `MemoriesRepository` 访问数据，远程适配器替换本地模拟，不重建项目。
- 内部业务使用 TanStack Start 服务端函数，外部回调用经过签名/身份验证的服务端入口；发布环境兼容性单独验证。
- 数据迁移含明确权限授予和行级隔离；成员权限与角色不存个人资料表。匿名写入不开放任意公开直接写数据库能力。
- 幂等键、事务与审核事件保障重复提交和状态变更；公开回应必须同时满足自身与原信的公开条件。
- 不修改 Git 历史；UI 批次不改 AGENTS.md 或 CI。必要架构规则只在获准的后端批次维护。
